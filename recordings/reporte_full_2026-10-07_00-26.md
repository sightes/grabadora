## 🔑 Conceptos Fundamentales

### Concepto 1: Variables y Almacenamiento en RAM
- **Definición:** Espacio de memoria temporal donde se guardan valores asignados durante la ejecución del código.
- **Ubicación física:** RAM del equipo/cloud.
- **Comportamiento:** Se conservan mientras dure la sesión activa. Si la máquina cierra o hay inactividad prolongada (20-30 minutos), las variables desaparecen.
- **Ejemplo:** `mensaje = "voy a aprender Python paso a paso hoy una noche lluviosa"` → se guarda en RAM como string de 57 caracteres.

### Concepto 2: Tipado Dinámico en Python
- **Definición:** Sistema que no requiere declaración explícita de tipo al crear la variable. El tipo se infiere según el primer valor asignado, pero puede modificarse libremente en cualquier momento.
- **Regla clave:** Siempre prevalece la última asignación realizada sobre una misma variable.
- **Ejemplo:** `cantidad = 3` → luego `cantidad = 4` → `registro_anterior = 3`. La variable `cantidad` ahora contiene `4`.

### Concepto 3: Tipos de Datos Primitivos
- **int:** Valor entero sin decimales. Ej: `minerales = 600` → `type(minerales)` devuelve `<class 'int'>`.
- **float:** Variable decimal. Ej: `suministro = 0.5` → `type()` devuelve `<class 'float'>`.
- **string:** Texto encerrado entre comillas. Ej: `"marine"` → `type()` devuelve `<class 'str'>`.
- **boolean:** Condición lógica binaria. Solo acepta `True` o `False` (case-sensitive). Usado para ciclos y condiciones.
- **None / NaN:** Representan datos desconocidos, faltantes o no aplicables en conjuntos de datos reales.

### Concepto 4: Clasificación de Datos
- **Datos estructurados:** Formato tabular organizado en filas y columnas. Ejemplos: Excel, SQL, PostgreSQL, MongoDB, archivos `.txt` organizados.
- **Datos no estructurados:** Sin formato rígido ni jerarquía clara. Ejemplos: imágenes, texto plano, pistas de audio, videos, cadenas de emails. Requieren OCR, extracción de texto o limpieza avanzada.

#### Ejercicio 7: Memoria, precisión y overflow
**Tema:** `float32` vs `float64` y saturación de RAM
**Enunciado:**
Un dataset contiene 5 millones de valores decimales. Calcula aproximadamente cuánta RAM ocupará si se almacenan como `float32` y como `float64`. Explica qué es un `stack overflow` en este contexto y por qué la clase mencionó que usar `float64` excesivamente puede colapsar la sesión en entornos como Colab. ¿Cuándo conviene usar `float32` en ciencia de datos?

**Datos:**
- `float32` = 4 bytes por valor
- `float64` = 8 bytes por valor
- Total valores = 5,000,000

**Resolución:**
1. RAM `float32`: `5,000,000 × 4 = 20,000,000 bytes ≈ 19.07 MB`.
2. RAM `float64`: `5,000,000 × 8 = 40,000,000 bytes ≈ 38.15 MB`.
3. En datasets reales (millones de filas × decenas de columnas), `float64` multiplica la ocupación rápidamente.
4. `Stack overflow` = saturación de memoria asignada al proceso; el sistema operativo corta la ejecución para protegerse.
5. Conviene `float32` cuando: se trabaja con ML/deep learning (pérdida mínima de precisión aceptable), se optimiza memoria/ancho de banda, o los recursos son limitados (Colab gratuito).
6. La clase señaló que científicos estadísticos suelen manejar estos trade-offs consciente mente.

**Respuesta:** 
`float32` → ~19 MB | `float64` → ~38 MB. `float64` duplica consumo y acelera el riesgo de `stack overflow` al saturar RAM. Se recomienda `float32` en pipelines grandes, ML y entornos con recursos acotados, manteniendo precisión suficiente para el análisis.

- **Corrección:** El *stack overflow* (desbordamiento de pila) ocurre cuando la **pila de llamadas de ejecución** (call stack) supera su límite asignado, generalmente por recursión infinita o profundidad excesiva de funciones. La saturación de RAM corresponde a un *out-of-memory error* o agotamiento del montón (heap).
